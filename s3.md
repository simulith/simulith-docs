# S3 — Simulith local runtime

Amazon S3 REST subset for local development with AWS CLI and SDKs (`--endpoint-url`).

> **Status (v0.9.0+):** buckets, object CRUD, ListObjectsV2, and **`simulith verify s3`** — Terraform planned.

---

## Available operations

| Operation | Status | Notes |
| --- | --- | --- |
| ListBuckets | Available | All buckets in local store |
| CreateBucket | Available | Idempotent when bucket already exists |
| DeleteBucket | Available | Empty bucket only (`BucketNotEmpty` otherwise) |
| PutObject | Available | Single-part upload; Content-Type from request header |
| GetObject | Available | Returns body with Content-Type, Content-Length, ETag |
| HeadObject | Available | Metadata only (existence check) |
| DeleteObject | Available | Idempotent (204 even when key was missing) |
| ListObjectsV2 | Available | `prefix`, `max-keys`, `continuation-token` (basic pagination) |
| simulith verify s3 | Available | `simulith verify s3 --skip-aws` (6 scenarios); parity with AWS creds |

## Quick test (AWS CLI)

With Simulith running on `:4566`:

```bash
aws s3api create-bucket --bucket my-app-data --endpoint-url http://127.0.0.1:4566
aws s3api put-object --bucket my-app-data --key config/app.json --body ./app.json --content-type application/json --endpoint-url http://127.0.0.1:4566
aws s3api list-objects-v2 --bucket my-app-data --prefix config/ --endpoint-url http://127.0.0.1:4566
aws s3api get-object --bucket my-app-data --key config/app.json /tmp/out.json --endpoint-url http://127.0.0.1:4566
aws s3api head-object --bucket my-app-data --key config/app.json --endpoint-url http://127.0.0.1:4566
aws s3api delete-object --bucket my-app-data --key config/app.json --endpoint-url http://127.0.0.1:4566
aws s3api delete-bucket --bucket my-app-data --endpoint-url http://127.0.0.1:4566
```

Expected: create/put/list/get/head return HTTP 200; delete-object and delete-bucket return HTTP 204.

## Storage layout

| Layer | Location |
| --- | --- |
| Bucket metadata | SQLite table `s3_buckets` |
| Object metadata | SQLite table `s3_objects` (Content-Type, ETag, size) |
| Object files | `{state-dir}/s3/{bucket}/{key}` |

Default state path: `./.simulith/state.db` → objects under `./.simulith/s3/`.

Object keys may include `/` (prefix paths). Metadata and files survive runtime restart.

---

## Limits (bucket lifecycle + objects)

- REST API only (not AWS JSON `POST /`)
- Path-style and virtual-hosted bucket URLs (`{bucket}.s3…`) on the runtime port
- Bucket names: 3–63 chars, lowercase DNS-style (see AWS S3 naming subset)
- Single-part objects only (no multipart upload)
- ListObjectsV2: max 1000 keys per page; opaque `continuation-token`
- ETag is MD5 hex of object bytes (quoted in response headers)
- DeleteBucket rejects non-empty prefixes (objects under the bucket)
- SigV4 validation optional (same as other services — `auth.validate_signatures`)

## Verify S3

Run curated S3 scenarios against Simulith (smoke) or compare against real AWS (parity):

```bash
# smoke — no AWS credentials needed
simulith verify s3 --skip-aws --endpoint http://127.0.0.1:4566

# parity — requires AWS credentials
simulith verify s3 --region us-east-1 --endpoint http://127.0.0.1:4566
```

Scenarios: `create-list-delete-bucket`, `put-get-object`, `head-object`, `delete-object`, `list-objects-v2-prefix`, `object-round-trip`.

Save a JSON report: `simulith verify s3 --skip-aws --save-last` (writes `.simulith/verify-last.json`).
